# Review Contractor Delivery

Use the user's existing project context, policies and tools. Ask only for missing information that materially changes the result. Accept authorized exports when live integrations are unavailable; distinguish unavailable evidence from negative evidence. Follow the requested depth: discussion and audit do not authorize implementation or external actions. Keep project-specific data in the project rather than this public skill.

At invocation, read [the corrective-feedback loop](references/feedback-loop.md) and [regression cases](references/regression-cases.md). Apply learned corrections below before choosing an approach.

## Workflow

1. Gather the agreed scope, acceptance criteria, period, deliverables, revisions, dependencies and time/payment model. If no benchmark was agreed, label comparisons exploratory rather than retroactively imposing a quota.

2. Inspect actual outputs and a representative quality sample. Normalize comparisons for complexity, research, review cycles and blocked time; do not infer productivity from logged hours alone.

3. Separate throughput, correctness, completeness and rework. Identify whether unclear briefs, missing access or operator delays explain gaps before attributing them to performance.

4. Prepare factual examples and questions for unresolved discrepancies. Propose a measurable next batch, clearer acceptance criteria or support needed, grounded in the existing agreement.

5. Keep personal data private and avoid automated accusations or payment changes. Produce a review draft; communicate externally only when authorized.

## Deliverable

Scope-versus-delivery comparison, quality findings, dependency analysis and a constructive next-batch brief.
