# Journal To Video

Use the user's existing project context, policies and tools. Ask only for missing information that materially changes the result. Accept authorized exports when live integrations are unavailable; distinguish unavailable evidence from negative evidence. Follow the requested depth: discussion and audit do not authorize implementation or external actions. Keep project-specific data in the project rather than this public skill.

At invocation, read [the corrective-feedback loop](references/feedback-loop.md) and [regression cases](references/regression-cases.md). Apply learned corrections below before choosing an approach.

## Workflow

1. Identify whether the user wants ideas, scripts or both. Read supplied context and preserve factual details, explicit emotions and distinctive phrases. Do not assume every reflection belongs to the same product or audience.

2. Cluster into distinct concepts with source excerpts, core truth, audience, potential format and missing context. Merge duplicates and separate stories with different payoffs.

3. Rank by specificity, relevance, available tension, usefulness and enough source depth to finish. Label each standalone, merge, cut or needs more source. Do not turn a tentative thought into a settled belief.

4. Write only requested scripts with a truthful opening, useful story/teaching beats and an earned payoff. Do not invent dialogue, events, outcomes or a product CTA. If hook-engine is available it can refine the selected concepts; it is optional.

5. Check each script against its source and read it aloud for natural phrasing. Keep private details out of shareable copy unless the user intentionally includes them. Flag gaps instead of supplying fictional autobiographical material.

## Deliverable

Prioritized concept map, source traceability, requested complete scripts and focused follow-up questions.

## Example request

> Use $journal-to-video: Find the strongest video ideas in this ramble and script the best two.
