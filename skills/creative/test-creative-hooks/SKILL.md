# Test Creative Hooks

Use the user's existing project context, policies and tools. Ask only for missing information that materially changes the result. Accept authorized exports when live integrations are unavailable; distinguish unavailable evidence from negative evidence. Follow the requested depth: discussion and audit do not authorize implementation or external actions. Keep project-specific data in the project rather than this public skill.

At invocation, read [the corrective-feedback loop](references/feedback-loop.md) and [regression cases](references/regression-cases.md). Apply learned corrections below before choosing an approach.

## Workflow

1. Identify the source asset, objective, audience and single variable to test. Preserve a control and title-free master. Confirm the available platform testing method and current eligibility before relying on it.

2. Generate truthful, meaningfully different hooks supported by the actual content. Do not change the promised result or imply evidence the asset does not contain.

3. Render variants with stable body, caption, CTA and export settings when testing titles alone. Assign IDs and record changed variable, source version and any accidental differences.

4. Inspect readability, safe areas, duration and payoff alignment. If a format cannot support the proposed test, say so and choose a supported format rather than treating all formats as interchangeable.

5. Define comparable observation windows and attention plus downstream metrics. Record distribution/time/audience differences and sample limits. Organic repeat-post comparisons are not automatically randomized tests; do not call a winner from incomparable reach.

## Deliverable

Control and variants, stable caption, manifest, QA notes and a bounded readout plan or actual readout if data exists.

> Use $test-creative-hooks: Make title variants while holding the video and caption constant.
