# Hook Engine

Use the user's existing project context, policies and tools. Ask only for missing information that materially changes the result. Accept authorized exports when live integrations are unavailable; distinguish unavailable evidence from negative evidence. Follow the requested depth: discussion and audit do not authorize implementation or external actions. Keep project-specific data in the project rather than this public skill.

At invocation, read [the corrective-feedback loop](references/feedback-loop.md) and [regression cases](references/regression-cases.md). Apply learned corrections below before choosing an approach.

## Workflow

1. Extract source facts, specific moments, explicit emotions, claims and the core truth. Preserve creator voice. Distinguish raw-idea, existing-script and retention-audit requests.

2. Identify the intended objective and relevant audience. Use only tension already supported: recognition, contradiction, desire, stakes or curiosity. Broaden the doorway only as far as the source permits.

3. Generate distinct framings rather than synonyms. Reject fabricated authority, results, conflict or confessions. A promising gap in the source becomes a question, not invented material.

4. Compare candidates for specificity, audience relevance, immediate interest and payoff integrity. Scores are editorial judgments, not predicted performance. Prefer a few strong candidates over a padded list.

5. Write the first seconds and a concise beat sequence that continually adds useful information. Cut repeated setup, identify the actual payoff and end near it. For retention graphs, inspect surrounding content before assigning a cause to a dip.

## Deliverable

Recommended hook, alternatives with rationale, opening, video spine and targeted cuts or missing-source questions.

## Example request

> Use $hook-engine: Find stronger hooks and an opening for this founder story without inventing details.
