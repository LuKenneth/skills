# Prepare Growth Brief

Use the user's existing project context, policies and tools. Ask only for missing information that materially changes the result. Accept authorized exports when live integrations are unavailable; distinguish unavailable evidence from negative evidence. Follow the requested depth: discussion and audit do not authorize implementation or external actions. Keep project-specific data in the project rather than this public skill.

At invocation, read [the corrective-feedback loop](references/feedback-loop.md) and [regression cases](references/regression-cases.md). Apply learned corrections below before choosing an approach.

## Workflow

1. Define the recipient’s decisions, date range and needed scope. Inventory campaign history, spend, acquisition, activation, retention, lifecycle messages and positioning sources.

2. Build a chronological experiment/change log. Preserve founder corrections with effective dates, distinguishing measured data, estimates and recollections. Supersede corrected claims throughout the packet.

3. Reconcile financial and user sources, definitions and comparable windows. Separate paid versus organic results, views versus unique reach, and tracked creator links versus untracked calls to action.

4. Explain outcomes with their attribution limits. No missing-link evidence is not proof of no creator impact. Repeated repost views do not establish unique audience size.

5. Produce a concise decision-oriented packet with source notes and questions worth resolving. If revising a packet, integrate addenda and clearly identify the replacement version; avoid making readers reconcile conflicting attachments.

## Deliverable

A shareable dated brief, experiment ledger, metric definitions, source notes and unresolved questions.

## Example request

> Use $prepare-growth-brief: Prepare a packet showing what we tried, what happened and what remains uncertain.

## Learned corrections

When corrective feedback follows this skill, update the relevant instruction and its regression case in the same turn using the linked loop. Keep project-only values in private project context; keep this section limited to reusable decision rules.
