# Refresh Social Proof

Use the user's existing project context, policies and tools. Ask only for missing information that materially changes the result. Accept authorized exports when live integrations are unavailable; distinguish unavailable evidence from negative evidence. Follow the requested depth: discussion and audit do not authorize implementation or external actions. Keep project-specific data in the project rather than this public skill.

At invocation, read [the corrective-feedback loop](references/feedback-loop.md) and [regression cases](references/regression-cases.md). Apply learned corrections below before choosing an approach.

## Workflow

1. Inventory requested placements and clarify whether copy, selection, styling or all three should change. Fetch supplied/authorized review sources and preserve stable source links, dates, ratings and attribution.

2. Select credible reviews relevant to the question each surface must answer. Prefer recency when useful without misrepresenting the overall review distribution. Never invent endorsements or imply permission beyond the source and applicable usage terms.

3. Preserve wording; clearly mark excerpts and translations. Do not splice statements into a stronger claim or change an individual rating to match the aggregate rating.

4. Adapt length and layout to each surface while retaining provenance. Keep remote paywall drafts distinct from published configurations. Match approved brand styles only where requested.

5. Read back every changed placement. Check narrow layouts, long names, accessible ratings, fallbacks and embeds. Report inaccessible surfaces and unpublished drafts explicitly rather than claiming an app-wide refresh.

## Deliverable

Source/placement manifest, verified revisions or drafts, screenshots where relevant, and remaining publication checks.

## Example request

> Use $refresh-social-proof: Refresh our onboarding, paywall and website reviews from recent store feedback.

## Learned corrections

When corrective feedback follows this skill, update the relevant instruction and its regression case in the same turn using the linked loop. Keep project-only values in private project context; keep this section limited to reusable decision rules.
