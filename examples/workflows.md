# Example workflows

These are synthetic task briefs. Each step is separately invokable; continue only within the user's requested scope.

## Improve an onboarding flow

1. **audit-onboarding:** “Map this fresh-install recording and event export. Identify where users fail to complete their first exercise. Do not change code yet.”
2. **polish-mobile-flow:** “Implement the selected navigation change. Preserve account recovery and show before/after captures for loading, failure and success.”
3. **prepare-mobile-release:** “Prepare a preview candidate and verify compatibility with the currently released clients.”

Outputs move from a sourced diagnosis to a reviewed change to a specific releasable candidate. Deployment remains a separate authorized action.

## Turn product value into an acquisition asset

1. **build-lead-magnet-funnel:** “Use these approved beginner exercises to create a short workbook, signup flow and delivery draft. Keep the resource useful on its own.”
2. **refresh-social-proof:** “Select exact review excerpts relevant to beginners for the resource page. Keep attribution and dates.”
3. **review-acquisition-experiment:** “Compare the resource campaign using these spend, signup and first-payment exports. Label immature cohorts and attribution gaps.”

Outputs connect an asset to a working journey and then to a measured readout. The third step needs actual results; it cannot infer lift from the existence of the funnel.

## Learn from a customer problem

1. **investigate-customer:** “Reconcile this account's payment and entitlement using these redacted exports.”
2. **diagnose-user-journey:** “Access is valid, but voice sessions fail on cellular. Compare version, network and event evidence.”
3. **find-support-friction:** “Check whether other recent cases show this cause and propose the smallest product or help-content improvement.”

A single account investigation and a population-level pattern review use different evidence and denominators.

## Learn from your own correction

“Your draft treated queued emails as delivered. Correct the packet, update the skill so it checks delivery evidence, and add a synthetic regression case.”

The expected result is a corrected artifact plus a local instruction/case diff, with no customer identifiers or automatic upstream publication. [Feedback behavior](../docs/learning.md) explains writable and read-only installations.
